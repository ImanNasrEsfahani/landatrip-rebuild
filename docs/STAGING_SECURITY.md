# Staging security controls

The staging site requires Caddy HTTPS and HTTP Basic access before Laravel login. Use a unique staging hostname and credentials, plus the five synthetic users. Store `.env.staging`, `.staging-access`, `.staging-credentials`, database backups, and server SSH keys outside Git. Rotate all temporary credentials after testing. Restrict host SSH and Docker access. Database port 3306 is never published. The local edge binds loopback only.

Laravel runs with `APP_ENV=staging`, `APP_DEBUG=false`, secure SameSite Lax cookies, a single HTTPS CORS origin, and a trusted proxy setting limited by the private network topology. The Caddy edge overwrites the forwarded scheme. Keep the staging application and Nginx off a host port. Keep API and browser sessions on the same origin. Caddy's Basic auth precedes all endpoints, including APIs and `/healthz`. API clients send Basic credentials in `Authorization` and a Laravel bearer token in `X-Staging-Api-Authorization`; Caddy maps the latter to upstream `Authorization` only after its Basic check, then strips the custom header.

`MAIL_MAILER=log`, `BROADCAST_CONNECTION=log`, and `QUEUE_CONNECTION=sync` prevent customer mail and queued delivery. SMS listeners already gate on production; use no live provider credentials. Never copy production data. Do not configure payment or travel provider secrets. Commercial checkout remains HTTP 409. `BOOKING_TEST_CHECKOUT_ENABLED=false`, empty `BOOKING_TEST_GATEWAY`, `TEST_ENABLED=false`, staging environment, and a different database keep the local E2E payment fixture unavailable. The fixture's original environment, database and token checks remain intact. A future interactive payment demonstration needs a separately reviewed staging simulation.

Known limits: HTTP Basic credentials are shared across test participants unless individually issued by an upstream access proxy; rotate them. The app has legacy features and third-party integrations not covered by the synthetic smoke suite. Inertia SSR is disabled in staging because the current routes do not render Inertia pages. Route caching is currently unavailable because legacy routes reuse a route name; configuration and views are cached. The scheduler executes legacy notification tasks, but staging mail is logged and SMS is production-gated. Review new integrations before enabling them. No live external deployment is part of this repository change.

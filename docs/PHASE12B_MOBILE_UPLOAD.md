# Mobile upload contract decision

No Dart, pubspec or bundled Flutter callers were found in this repository; searches for file-upload/uploadFileToCloud find only the Laravel route and existing tests. No external client checkout was available. The owner explicitly approved the intended contract: HTTP 201, application/json, exactly {"data":"<authorized-file-url>"}. This is an owner-approved intended contract, not a claim of verified compatibility with a shipped Flutter app.

The existing POST /api/app/v1/file-upload route remains. It now requires Sanctum, validates multipart file via TemporaryUpload and returns an authenticated URL to a new common API download route. The client must send its Sanctum token on upload and on download. The URL contains only an ID and expires with the upload's existing 24-hour TTL; authorization also rejects consumed IDs, ownerless legacy rows and other users. No bearer token or disk path is embedded in the URL. No public copy, signed public URL or legacy migration is created. Confirm the actual mobile image/download loader can attach Authorization before release.

The former route was anonymous, wrote a timestamp file and terminated with dd(bool); its remaining URL code was unreachable and referenced an undefined variable. That observable defect is replaced under the owner decision. There are still exactly 49 mobile v1 routes, with unchanged methods and URIs. This endpoint alone intentionally changes from anonymous/debug output to authenticated HTTP 201 JSON; the compatibility test records 35 protected and 14 public mobile routes. Other mobile endpoint contracts are unchanged. Common route inventory becomes 351 total / 216 API.

Tests use synthetic private bytes and verify token authentication, exact response envelope, authorized download, outsider denial, expiration, invalid input and no public files. Bytes are retained after expiry as required by the existing preservation plan. No production or legacy files are touched.
